# Corrected data plan (user-reviewed ranking)

The philosophy stands (observe more milestones, shorten the forecast
horizon), the ranking does not. Corrected:

1. **Planning phasing drawings and unit schedules** — the missing bridge
   between unit addresses and BCMS phases. Source: local PDF corpus +
   iDocsWeb/agile pulls + FOI if needed.
2. **Small ECAD/provider pilot** — standardise PPR addresses, geolocate
   units, combine with phase plans; repairs labels directly. Created Date
   semantics unverified; ECAD carries no phase identifiers.
3. **SEAI BER registration + field audit** — inspect exactly which
   geographic/address fields survive anonymisation (~75% record coverage
   reported); final BER is a near-completion proxy, not a legal completion
   date. Useful at development level if linkage permits, otherwise an
   aggregate completion feature.
4. **ESB/CSO data request or research collaboration** — energisation is the
   strongest completion observation; access uncertain; RMF route requires
   an approved statistical research project, not unit-record extraction for
   a commercial model.
5. **Targeted FOIs** (Part V, HSA, Uisce, contributions) — useful
   additional events; do not assume national, structured or address-level
   returns. HSA AF1/AF2 are notifications, not proof of physical start.
6. **CRO + Land Registry** — developer identity and stall-tail prediction
   only; low-medium for ordinary construction duration.

Immediate accuracy play: planning phase maps + address standardisation +
PPR, then BER if its actual fields permit development-level linkage.
Complete the free BER field audit and a small ECAD/phasing pilot before
